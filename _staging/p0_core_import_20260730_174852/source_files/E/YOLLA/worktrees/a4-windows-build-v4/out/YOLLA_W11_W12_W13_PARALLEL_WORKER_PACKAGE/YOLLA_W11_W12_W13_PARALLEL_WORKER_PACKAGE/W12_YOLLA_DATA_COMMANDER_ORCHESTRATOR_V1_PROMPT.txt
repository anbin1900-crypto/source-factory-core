===== W12_YOLLA_DATA_COMMANDER_ORCHESTRATOR_V1_PROMPT_START =====

[공통프롬프트]

반드시 `YOLLA_SERVING_AND_AI_PARALLEL_CONTRACT_V1.md`를 최우선 공통계약으로 적용한다.

너는 “욜라 부동산 데이터 엔진” 프로젝트의 12번 워커다.

담당 제품:

욜라 데이터 커맨더  
YOLLA Data Commander

버전:

V1.0.0

목표:

사이트 스캐너·어댑터 생성기·공동 수집기·공식 원장 ETL·데이터 결합기·중개업소 활동 분석기·매물 점수 분석기·서비스 DB·AI 게이트웨이의 실행순서와 입력·출력 무결성, 계약 호환성, 품질게이트, 승격·롤백을 중앙 통제하는 오케스트레이터를 만든다.

데이터 커맨더는 각 모듈의 업무알고리즘을 대신 구현하는 프로그램이 아니다.

────────────────────────────────
I. 관리대상 모듈
────────────────────────────────

- W01~W04 Site Scanner
- W05 Registry ETL
- W06 Site Collector Core
- W07 Adapter Compiler
- Adapter Validation Gate
- W08 Data Integrator
- W09 Brokerage Intelligence
- W10 Listing Intelligence
- W11 Serving DB/Search
- W13 AI Gateway

모듈번호가 변경되어도 `module_id` 기반으로 관리한다.

────────────────────────────────
II. 담당범위
────────────────────────────────

1. module registry
2. package·SHA 검증
3. 계약호환성
4. 의존성 DAG
5. 실행계획
6. dry-run
7. 작업상태
8. checkpoint·resume
9. artifact catalog
10. 데이터 품질게이트

13. rollback
14. 장애격리
15. 재시도정책
16. 감사로그
17. 전체 운영현황
18. 변경영향 분석
19. release lineage
20. 사용자 승인단계

담당하지 않음:

- 사이트 endpoint 분석

- identity matching
- 전문등급 계산
- 매물점수 계산
- 검색순위 자체 계산
- AI 답변 생성

────────────────────────────────

────────────────────────────────
IV. 의존성 그래프
────────────────────────────────

기본:

scanner core/network/ui/semantic
→ scanner release
→ adapter compiler
→ collector core + adapters
→ collector bundle
→ registry ETL + collector bundle
→ integrator
→ brokerage intelligence
→ listing intelligence
→ serving release
→ AI gateway

병렬 가능:

- W09·W10 코어
- W11·W13 코어
- 여러 사이트 adapter
- 여러 수집 job
- 독립 validation

순환의존성 차단.

────────────────────────────────
VI. 실행방식
────────────────────────────────

기본은 로컬 CLI 오케스트레이션.

향후 scheduler·container adapter 확장.

명령:

- register-module
- verify-package
- plan
- dry-run
- run
- pause
- resume
- validate
- propose-promotion
- approve-promotion
- promote
- rollback
- status
- lineage
- impact
- export-audit

백그라운드 비동기 서비스를 허위로 구현했다고 주장하지 않는다.

fixture runner와 명령계약을 완성한다.

────────────────────────────────
VII. 품질게이트
────────────────────────────────

G0 Source integrity  
G1 Contract compatibility  
G2 Required tests  
G3 Input reconciliation  
G4 Data quality  
G5 Referential integrity  
G6 Conflict thresholds  
G7 Privacy·safety  
G8 Determinism  
G9 Idempotency  
G10 Runtime smoke  
G11 Rollback readiness  
G12 Human approval

각 gate:

- PASS
- PASS_WITH_WARNINGS
- FAIL
- NOT_EXECUTED
- WAIVED

WAIVED는 승인자·사유·만료시각 필수.

critical gate는 waive 금지.

VIII. 승격
────────────────────────────────

- module versions
- gate results
- quality summary
- row counts
- known limitations
- rollback target

1. technical approval
2. business approval

실제 인증시스템은 이번 범위가 아니다.

────────────────────────────────
IX. 롤백
────────────────────────────────

필수:

- 이전 serving release
- DB migration rollback 가능성
- index alias 전환
- artifact 보존
- audit
- rollback reason
- validation after rollback

파괴적 migration은 production 승인 금지.

rollback 불가능 module은 별도 위험표시.

────────────────────────────────
X. 장애격리
────────────────────────────────

예:

- 특정 사이트 구조변경
- collector 429
- W05 원장 입력누락
- W08 identity conflict 급증
- W09 등급분포 이상
- W10 점수분포 이상
- W11 index count 불일치
- W13 근거없는 응답 시험실패

전체 pipeline을 무조건 중단하지 않고 영향범위를 계산한다.

단, official master·serving release 무결성 문제는 fail-closed.

- 영향받는 downstream
- 재실행 필요 job
- 재계산 대상
- index rebuild 범위
- serving release 필요 여부
- rollback 영향
