===== W02_YOLLA_NETWORK_CONTRACT_DRIFT_ANALYZER_V1_PROMPT_START =====

[공통프롬프트]

반드시 `YOLLA_SITE_SCANNER_WAVE2_COMMON_CONTRACT_V1.md`를 최우선으로 적용한다.

너는 “욜라 사이트 스캐너 Wave 2”의 2번 워커다.

담당 제품:

욜라 네트워크 계약 변화 분석기  
YOLLA Network Contract Drift Analyzer

버전:

V1.0.0

목표:

서로 다른 시점에 생성된 Network MRI 보고서와 endpoint catalog를 비교하여 API endpoint·요청 파라미터·body schema·response schema·pagination·GraphQL·WebSocket 구조의 변화를 판정하고, 공동 수집기와 사이트 어댑터에 필요한 변경요청서를 자동 생성한다.

────────────────────────────────
I. 기준 입력
────────────────────────────────

기준 ZIP:

`W02_SITE_SCANNER_NETWORK_MRI_CORRECTED.zip`

기대 SHA-256:

`504c631d68a4a6a786734fbd90ea804511c75bae396b2543b72285b95576cb91`

기준 ZIP을 수정하지 않는다.

별도 애드온 프로젝트로 개발한다.

────────────────────────────────
II. 입력
────────────────────────────────

지원 입력:

1. Network MRI report JSON
2. endpoint catalog CSV·JSON
3. event JSONL
4. scan package
5. adapter endpoint definition
6. 이전 drift baseline

최소 두 시점:

- baseline
- candidate

복수시점 추세도 지원한다.

────────────────────────────────
III. 변화유형
────────────────────────────────

endpoint:

- ADDED
- REMOVED
- PATH_CHANGED
- METHOD_CHANGED
- ORIGIN_CHANGED
- AUTH_DEPENDENCY_CHANGED
- CONTENT_TYPE_CHANGED
- STATUS_PATTERN_CHANGED

request:

- QUERY_KEY_ADDED
- QUERY_KEY_REMOVED
- QUERY_TYPE_CHANGED
- BODY_SCHEMA_CHANGED
- HEADER_REQUIREMENT_CHANGED
- GRAPHQL_OPERATION_CHANGED
- GRAPHQL_VARIABLE_CHANGED

response:

- ROOT_TYPE_CHANGED
- FIELD_ADDED
- FIELD_REMOVED
- FIELD_TYPE_CHANGED
- NULLABILITY_CHANGED
- ARRAY_SHAPE_CHANGED
- ID_PATH_CHANGED
- ERROR_ENVELOPE_CHANGED

flow:

- PAGINATION_CHANGED
- CURSOR_PATH_CHANGED
- TOTAL_COUNT_PATH_CHANGED
- MAP_BOUNDS_CHANGED
- RATE_LIMIT_SIGNAL_CHANGED
- WEBSOCKET_MESSAGE_CHANGED
- EVENTSOURCE_EVENT_CHANGED

────────────────────────────────
IV. Severity
────────────────────────────────

- INFO
- MINOR
- MAJOR
- CRITICAL

예:

INFO:
optional response field 추가

MINOR:
fallback selector와 무관한 query 추가

MAJOR:
필수 field path 삭제, pagination 변경

CRITICAL:
목록·상세 endpoint 제거, 인증필수 전환, 응답 root 전환, 중개업소 ID 경로 소멸

severity 규칙은 구성파일로 둔다.

────────────────────────────────
V. Endpoint matching
────────────────────────────────

시점 간 endpoint 연결근거:

- endpoint signature
- method
- normalized path
- GraphQL operationName
- query key set
- request schema
- response schema
- classification
- initiator route
- field overlap

정확 일치가 없으면 candidate match score를 계산한다.

불확실한 연결은 확정하지 않는다.

- MATCHED
- PROBABLE
- AMBIGUOUS
- UNMATCHED

────────────────────────────────
VI. Schema diff
────────────────────────────────

JSON schema tree diff:

- path
- before
- after
- change type
- required 여부
- sample frequency
- affected entity field
- evidence refs

배열 내부 object schema를 별도로 비교한다.

샘플 한 번만 없는 field를 제거로 단정하지 않는다.

관찰 coverage와 출현빈도를 함께 본다.

────────────────────────────────
VII. Adapter impact
────────────────────────────────

입력 adapter의 다음을 검사한다.

- endpoint
- request parameters
- response paths
- pagination
- identity keys
- field mapping
- drift rules

출력:

- unaffected rules
- update required
- disable required
- rescan required
- manual review
- proposed patch candidates

실제 adapter 파일을 자동 덮어쓰지 않는다.

────────────────────────────────
VIII. 변경요청서
────────────────────────────────

생성:

`ADAPTER_CHANGE_REQUEST.json`

필드:

- site_id
- baseline scan SHA
- candidate scan SHA
- drift run ID
- severity
- affected adapter version
- affected routes
- affected endpoints
- affected fields
- proposed changes
- unresolved
- evidence refs
- required tests
- recommended action

추가:

`ADAPTER_PATCH_SUGGESTION.diff`

이 파일은 제안이며 자동적용 금지.
