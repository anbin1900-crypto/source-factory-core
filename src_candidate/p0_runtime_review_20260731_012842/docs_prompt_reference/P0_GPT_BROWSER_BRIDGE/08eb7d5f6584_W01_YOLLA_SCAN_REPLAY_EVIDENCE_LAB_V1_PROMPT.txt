===== W01_YOLLA_SCAN_REPLAY_EVIDENCE_LAB_V1_PROMPT_START =====

[공통프롬프트]

반드시 `YOLLA_SITE_SCANNER_WAVE2_COMMON_CONTRACT_V1.md`를 최우선으로 적용한다.

너는 “욜라 사이트 스캐너 Wave 2”의 1번 워커다.

담당 제품:

욜라 스캔 재생·증거 연구소  
YOLLA Scan Replay and Evidence Lab

버전:

V1.0.0

목표:

사이트에서 한 번 기록한 스캔 세션을 이식 가능한 무결성 패키지로 내보내고, 다른 실행환경에서 네트워크 요청을 다시 보내지 않은 채 이벤트·증거·라우트·페이지 상태를 결정적으로 재생하여 W2·W3·W4 모듈을 반복 검증할 수 있는 오프라인 재생·증거보관 애드온을 만든다.

────────────────────────────────
I. 기준 입력
────────────────────────────────

반드시 다음 기준 ZIP에서 시작한다.

`W01_SITE_SCANNER_CORE_CORRECTED.zip`

기대 SHA-256:

`5794e83d002587eaea3ffed2fa3a859e0f9d650038d4a34e440af3c72e0583f9`

SHA가 다르면 소스를 변경하지 말고 `SOURCE_SHA_MISMATCH`로 종료한다.

기준 ZIP은 수정하지 않는다.

별도 프로젝트로 개발한다.

────────────────────────────────

- 실제 사이트 구조분석
- 실제 네트워크 요청 재전송

- W04 최종 V1.0 소스 직접 변경

────────────────────────────────
III. 핵심 원칙
────────────────────────────────

1. 오프라인 재생이 기본이다.
2. replay는 저장된 event envelope를 모듈 event bus에 다시 방출하는 것이다.
3. 실제 fetch·XHR·WebSocket을 재현하지 않는다.
4. 원래 시간 간격과 가속시간을 모두 지원한다.
5. 동일 package와 동일 모듈버전은 동일 결과를 만들어야 한다.
6. 증거 blob은 SHA-256 주소로 저장한다.
7. 누락된 blob·깨진 manifest를 명확히 실패 처리한다.
8. redaction을 통과하지 않은 package는 import 차단한다.
9. 원본 session·scan ID와 replay session ID를 분리한다.
10. replay 결과는 원본 관찰처럼 위장하지 않는다.

────────────────────────────────
V. Export snapshot
────────────────────────────────

export 시작 시 snapshot boundary를 고정한다.

포함:

- session
- scan
- module registry
- events
- evidence index
- evidence blobs
- route states
- endpoint signatures
- selector signatures
- entity candidates
- field candidates
- adapter blueprints
- validation reports
- checkpoint
- report

export 중 새 이벤트는 다음 package에 포함한다.

성공 후에만 export ledger를 갱신한다.

────────────────────────────────
VI. Evidence CAS
────────────────────────────────

저장키:

`sha256:<content_hash>`

규칙:

- 동일 content hash 하나만 저장
- MIME type 기록
- 원본크기·저장크기
- 압축여부
- redaction policy
- evidence 참조수
- 첫·최근 참조
- orphan detection
- garbage collection은 분석만 제공하고 자동삭제 금지

────────────────────────────────
VII. Replay engine
────────────────────────────────

모드:

- REAL_TIME
- ACCELERATED
- STEP
- SEEK
- MODULE_ONLY
- FULL_PIPELINE

속도:

- 0.25x
- 0.5x
- 1x
- 2x
- 4x
- 10x
- MAX_DETERMINISTIC

순서:

1. package 검증
2. module version 검증
3. replay session 생성
4. 초기 scan context 복원
5. event sequence 순서대로 방출
6. evidence ref resolver 제공
7. module output 수집
8. replay report 생성

동일 occurred_at 이벤트는 원본 sequence로 정렬한다.

────────────────────────────────
VIII. 안전
────────────────────────────────

replay 환경에서 다음 API를 차단하거나 mock으로 대체한다.

- fetch
- XHR send
- WebSocket send
- EventSource 신규연결
- beacon
- location navigation
- window.open
- form submit
- DOM mutating click executor

모듈이 실네트워크를 요청하면 `REPLAY_NETWORK_ACCESS_BLOCKED`.

────────────────────────────────
IX. Package repair diagnostics
────────────────────────────────

자동수정이 아니라 진단한다.

탐지:

- 누락 file
- SHA mismatch
- 잘못된 gzip
- JSONL line 오류
- orphan evidence
- duplicate event ID
- sequence gap
- 잘못된 timestamp
- module version mismatch
- redaction failure
- unknown contract

출력:

`SCAN_PACKAGE_REPAIR_REPORT.json`

원본 package를 덮어쓰지 않는다.
